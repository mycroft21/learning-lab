> 한 줄 요약: 로컬 LLM 하드웨어를 고를 때 파라미터 수와 총 메모리 용량에 홀리기 쉬운데, 토큰 생성 속도를 정하는 건 메모리 대역폭이다. "로딩 가능"과 "쓸 만한 속도로 돈다"는 완전히 다른 얘기다.

## 배운 맥락

로컬 코딩 에이전트를 돌릴 머신을 고민하다가 "메모리 몇 GB면 몇 B 모델까지 되나", "여러 대
붙이면 상위 모델급 되나"가 궁금해서 다른 AI와 문답을 시작했다. 답변에는 유용한 큰 그림과 함께
사실관계 오류가 몇 개 섞여 있어서, 검색으로 교정하며 정리했다.

## 메모리는 세 가지를 구분해야 한다 — 용량 ≠ 대역폭

로컬 LLM 성능을 좌우하는 메모리는 사실 별개의 세 축이다. 이걸 뭉뚱그리면 판단이 어긋난다.

- **용량(GB)** — 모델 가중치 + KV 캐시가 물리적으로 들어가느냐. "몇 B까지 로딩 가능"을 결정.
- **대역폭(GB/s)** — 초당 얼마나 데이터를 GPU/NPU에 밀어넣느냐. **토큰 생성 속도를 결정**.
  autoregressive 추론은 토큰 하나 뽑을 때마다 전체 가중치를 메모리에서 읽어야 해서, 속도는
  사실상 대역폭에 지배당한다.
- **연산 성능(FLOPS)** — 입력 처리나 학습에서 중요. 토큰 생성 속도엔 상대적으로 덜 결정적.

"메모리 많으면 빠르다"가 틀린 이유가 여기 있다. 용량이 커도 대역폭이 낮으면 큰 모델은
느리게만 돈다.

## 양자화와 용량 계산 — 단순 곱셈의 함정

가중치 메모리는 대략 (파라미터 수 × 바이트/파라미터)다. 4bit 양자화 기준으로 계산하면
그럴듯한 숫자가 나오는데, **이 계산엔 대개 KV 캐시가 빠져 있다.** KV 캐시는 컨텍스트
길이에 비례해 늘고, 긴 컨텍스트에서는 수십 GB를 추가로 먹는다. "로딩 가능"과 "실사용
가능"은 다르다.

## 브랜드명이 성능 인상을 왜곡하는 사례

최상급 브랜드 라인업으로 나온 통합 메모리 제품 하나를 찾아봤는데, 용량은 크지만
**메모리 대역폭이 애플 실리콘 상위 칩보다도 낮은** 경우가 있었다. 제3자 벤치마크상 대형
모델에서 초당 토큰 수가 낮게 나온다는 보고도 있었다. 즉 브랜드 이름이 주는 인상과 실제
성능 포지션(중소형 모델 프로토타이핑·파인튜닝용)이 다를 수 있다 — "이름 = 최상급"이라는
프레이밍을 그대로 믿으면 안 된다.

## 여러 대 클러스터 = 상위 모델급? — 구조적으로 아니다

애플 실리콘은 고속 GPU 인터커넥트가 없다. 여러 대를 붙여도 "하나의 초대형 모델을 여러
장비에 쪼개 추론"하는 데는 부적합하고, 네트워크 병렬은 오버헤드가 크다. 결국 "여러 개의
중형 모델을 동시에 돌리는" 구조지 "하나의 초대형 모델을 만드는" 구조가 아니다. 그리고 더
근본적으로, 최상위 모델 품질은 하드웨어만의 문제가 아니다 — 학습 데이터 규모, 정렬 품질,
추론 최적화가 핵심이라 연산 장비를 붙인다고 재현되지 않는다.

## 토큰 속도 수치는 대부분 추정치 — 곧이곧대로 믿지 말 것

다른 AI가 제시한 속도 표는 실측이 아니라 일반 추세로 지어낸 추정치였다. 방향성(작은 모델일수록
빠름)은 맞지만 절대 수치는 근거가 약했다. 하드웨어 성능 표를 볼 때는 "실측이냐 추정이냐"를
항상 구분해야 한다.

## 걸렸던 지점 / 인식이 바뀐 것

처음엔 나도 "용량이 클수록 좋고, 파라미터 수가 클수록 똑똑하다"는 프레임으로 접근했다.
그런데 파고 보니 (1) 용량은 로딩 가능 여부만 정하고 속도는 대역폭이 정한다는 것, (2) 그래서
용량은 큰데 대역폭이 낮은 장비는 큰 모델에서 오히려 느리다는 것, (3) 브랜드명이 성능 인상을
왜곡한다는 것이 드러났다. 그리고 다른 AI를 신뢰하되 사실 단정(제품 존재 여부 같은 것)은
반드시 검증해야 한다는 것도 다시 확인했다 — 자신만만한 오답이 하마터면 노트에 그대로
박힐 뻔했다.

## ROI 관점 정리

로컬 코딩 에이전트 용도라면 가성비 최적점은 중형(70B급) Q4~Q6 수준이고, 최상위 모델을
로컬로 대체하는 현실적 방법은 개인 예산 수준에선 사실상 없다 — 학습·정렬 품질 문제이지
장비 문제가 아니기 때문이다. 개인 사용량이면 상위 API 비용이 수십~100달러 선이라 순수
비용 회수 논리로는 로컬 투자가 잘 안 맞고, "로컬 자율성·프라이버시·오프라인"이라는 다른
가치가 있을 때 정당화된다. 실전 해법은 대체로 로컬 중형 모델 + 상위 API 병행이다.

## 정리

파라미터 수와 총 메모리 용량에 홀리기 쉬운데, 토큰 속도를 정하는 건 메모리 대역폭이다.
"로딩 가능"과 "쓸 만한 속도로 돈다"는 완전히 다른 얘기고, 용량 큰데 대역폭 낮은 장비가
그 함정의 산 증거다. 그리고 다른 AI의 사실 단정은 꼭 검증하자 — 없는 걸 있다고 우기는
것보다 있는 걸 없다고 단정하는 오류가 더 위험하다.
