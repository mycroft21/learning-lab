Claude Code, pi(개인 커스텀 하네스), opencode 세 가지 AI 코딩 도구를 같이 쓰면서, "이런 건 이렇게 해달라" 같은 공통 규칙을 한 곳만 고치면 전부 반영되게 만들고 싶었다. 그런데 정작 이 작업 도중에, 작업 자체보다 오래 남은 건 설정 파일 위치를 찾은 것보다 "조사해달라"는 말을 "적용해달라"로 두 번이나 잘못 읽었다는 사실이었다.

## 전역 설정 파일이 하네스마다 다른 자리에 있다

Claude Code는 `~/.claude/CLAUDE.md`, opencode는 `~/.config/opencode/AGENTS.md`에 있었다. pi는 처음엔 전역 설정 파일이 아예 없는 줄 알았다. `~/.pi/agent/settings.json`을 봐도 시스템 프롬프트 필드가 안 보였기 때문이다.

문서나 추측으로는 답이 안 나와서, pi의 실제 npm 패키지를 열어 리소스 로더 소스(`dist/core/resource-loader.js`)를 직접 읽었다. `AGENTS.override.md` → `AGENTS.md` → `AGENTS.MD` → `CLAUDE.md` → `CLAUDE.MD` 순서로 설정 디렉터리(`agentDir`) 안을 찾고, 거기서부터 작업 디렉터리까지 상위로 올라가며 각 레벨의 파일도 추가로 로드하는 구조였다. 전역 파일이 없었던 게 아니라, 그 자리에 그냥 아무도 파일을 만들어두지 않았을 뿐이었다.

세 도구를 소스 레벨로 까보니 공통점이 두 개 나왔다. 같은 파일명 컨벤션(`AGENTS.md`, 일부는 `CLAUDE.md`까지 폴백)을 쓰고, 작업 디렉터리에서 상위로 캐스케이딩한다는 것. 그런데 내용을 다른 파일에서 끌어오는 "import" 문법은 하나도 없었다. 그냥 파일 하나를 통째로 읽어 컨텍스트에 붙이는 방식이었다.

## import가 안 되면 심링크로 묶는다

콘텐츠 include 기능이 없으니, 여러 하네스가 같은 내용을 보게 하려면 OS 레벨에서 풀어야 했다. 한쪽 설정 파일을 다른 쪽으로 심링크 걸어서, 한 곳만 고치면 둘 다 갱신되게 만들었다. 나머지 한 곳은 이미 코딩 컨벤션 문서가 따로 길게 있어서 통째로 심링크하기엔 성격이 안 맞았고, 공통 규칙 몇 줄만 복사해 넣었다. 완전한 단일 소스는 아니지만, 파일 성격이 다를 땐 억지로 하나로 묶는 것보다 일부 중복을 감수하는 쪽이 나았다.

## "찾아봐줄래?"를 승인으로 읽은 두 번

이 작업 도중, 조사·의견을 구하는 요청을 받고 조사한 내용을 확인도 안 받은 채 바로 설정 파일에 반영해버린 적이 두 번 있었다. 지적을 받고 나서 정확히 뭐라고 들었냐면, "AI가 입력에 말을 할 게 있냐 찾자마자 내 확인도 안 받고 수정을 시작했지"였다.

돌아보면 패턴이 뚜렷했다. "~같은데", "~인 것 같아" 같은 잠정적인 말투가 실제로는 "아직 확정 아님"을 뜻하는데, 그걸 승인으로 당겨 읽기가 쉬웠다. 한 번은 그럭저럭 넘어갔지만 두 번째는 명확히 지적당했다. "구체화 중인 대화"와 "이미 확정한 반복 작업"을 구분해서, 애매하면 초안만 보여주고 명시적인 확정 문구를 기다리는 쪽으로 조정했다.

## 덤으로 하나 더

같은 작업 도중에 만든 문서(내부 서버 IP 같은 게 담긴 엑셀)를 사용자 문서 폴더에 저장해뒀었는데, 나중에 알고 보니 이 맥에 iCloud "데스크탑 및 문서 폴더" 동기화가 켜져 있어서 그 폴더 전체가 자동으로 클라우드에 올라가고 있었다. `defaults read com.apple.finder`로 관련 값을 확인하고서야 알았다. 민감한 파일의 저장 위치를 정할 때 "이 폴더가 로컬에만 있는 게 맞나"를 당연하게 여기면 안 된다는 걸 새로 배웠다.

## 되돌아보면

설정 파일 자리는 관례처럼 보이지만 도구마다 실제 구현은 다 달랐다. 사람의 말투도 관례적으로는 "제안"처럼 들리지만 맥락에 따라 승인으로 오해되기 쉬웠다. 폴더 위치도 겉보기엔 로컬 같지만 실제로는 클라우드 동기화 중일 수 있었다. 세 가지 다 "보이는 대로 믿지 말고 실제 동작·의도를 한 번 더 확인한다"는 같은 주제였다 — 그리고 세 번째는 확인 없이 넘어갔다가 실제로 겪었다.
